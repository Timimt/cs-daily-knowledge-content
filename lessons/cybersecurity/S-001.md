## 學習目標

讀完這一課，你應該能分辨對稱式加密與非對稱式加密的工作方式，說明為什麼 TLS、檔案加密與數位簽章經常同時使用 AES 和 RSA，並理解「演算法安全」不能取代「金鑰管理」。

## 先從一把鑰匙與兩把鑰匙說起

加密的目的，是讓沒有正確金鑰的人即使拿到密文，也無法有效率地還原原始內容。AES 和 RSA 最大的差別，不是誰比較新，而是它們假設的「金鑰關係」不同。

### AES：傳送端與接收端共用同一把秘密金鑰

AES（Advanced Encryption Standard，進階加密標準）是**對稱式加密**。傳送端與接收端必須持有同一把金鑰，或至少持有能快速推導出相同金鑰的秘密資料。

如果我們把明文記作 $P$、金鑰記作 $K$、密文記作 $C$，概念上可以寫成：

$$
C = \operatorname{AES-Encrypt}(K, P)
$$

解密時使用相同金鑰：

$$
P = \operatorname{AES-Decrypt}(K, C)
$$

AES 每一次處理固定大小的資料區塊。以 AES-256 為例，它使用 256 位元金鑰；資料則依模式（例如 GCM）分割與認證。AES-GCM 除了保密，還能檢查密文是否被篡改。

### RSA：一把公開、一把保密

RSA 是**非對稱式加密**，每個人有一組數學上相關的金鑰：

- 公鑰可以公開，常用來加密或驗證簽章。
- 私鑰必須保密，常用來解密或建立簽章。

RSA 的基礎之一是模數 $n$：

$$
n = p \times q
$$

其中 $p$ 和 $q$ 是兩個很大的質數。只知道 $n$ 時，要把 $n$ 分解成 $p$ 與 $q$ 非常困難，這個困難性是 RSA 安全假設的重要部分。實務計算不是一句「大數分解很難」就結束，還需要正確的填充、金鑰長度與協定設計。

## 為什麼不全部使用 RSA

RSA 能解決「雙方原本沒有共同秘密」的問題，但直接拿 RSA 加密大量檔案並不實用。它的數學運算比 AES 昂貴，而且可處理的資料量小。AES 則適合大量資料，運算速度快，但雙方必須先安全地取得共同金鑰。

因此常見設計是**混合式加密**：

1. 隨機產生一把只用一次的 AES 工作金鑰。
2. 使用 AES 金鑰加密大量資料。
3. 使用對方的 RSA 公鑰包裝 AES 工作金鑰。
4. 接收方先用私鑰解出 AES 金鑰，再解密資料。

| 比較項目 | AES | RSA |
|---|---|---|
| 金鑰關係 | 對稱，共用秘密 | 非對稱，公鑰與私鑰成對 |
| 大量資料 | 適合 | 不適合直接處理大量資料 |
| 典型用途 | 檔案、資料庫欄位、TLS 連線內容 | 金鑰交換輔助、簽章、憑證 |
| 主要風險 | 金鑰外洩或模式使用錯誤 | 私鑰外洩、填充錯誤、金鑰太短 |

## 用程式碼理解責任分工

下面的 C++ 是概念示意，不是可直接上線的密碼學實作：

```cpp
auto sessionKey = randomBytes(32);            // AES-256 工作金鑰
auto ciphertext = aesGcmEncrypt(sessionKey, fileData);
auto wrappedKey = rsaOaepEncrypt(peerPublicKey, sessionKey);

send(wrappedKey);
send(ciphertext);
```

這段程式碼真正重要的是責任分離：AES 保護資料，RSA 保護那把短期工作金鑰，而不是讓 RSA 獨自承擔所有工作。

## 真實應用：HTTPS 與數位簽章

當瀏覽器建立 HTTPS 連線時，TLS 會透過金鑰協商與憑證驗證，取得或產生連線所需的對稱金鑰，再用 AEAD 類型的演算法保護大量網路資料。不同 TLS 版本與金鑰交換方式細節不同，但都不應把「RSA 比 AES 弱」簡化成單一排名。

RSA 也常與數位簽章概念一起出現。簽章和加密不是同一件事：加密重視內容保密，簽章重視確認來源與資料是否被修改。實際協定會選擇適合的簽章演算法與填充方式。

## 今日重點整理

- AES 是對稱式加密，適合大量資料。
- RSA 是非對稱式加密，公鑰可公開，私鑰必須保密。
- 混合式加密通常用 RSA 或金鑰協定保護短期 AES 金鑰。
- 演算法名稱正確，不代表實作安全；填充、亂數、金鑰保存與協定版本同樣重要。

## 延伸思考

如果攻擊者取得伺服器的 RSA 私鑰，過去攔截到的加密流量是否一定都能解密？答案取決於 TLS 版本、是否使用前向保密，以及金鑰如何交換。這個問題可以連到下一課的金鑰生命週期與憑證管理。
