## 學習目標

讀完這一課，你應該能粗略說出 HTTPS 建立連線時發生哪些大事：協商參數、驗證憑證、交換金鑰，最後用 AEAD 保護資料。

## 為什麼需要 TLS

HTTP 是明文，路徑上的任何節點都可能看到或修改內容。TLS 在 HTTP 底下建立一層安全通道，提供機密性、完整性與伺服器身分驗證。網址欄的鎖頭代表「連線有 TLS」，不代表「網站一定善良」。

## 握手做了什麼

以 TLS 1.3 為例，握手階段大幅簡化：

1. Client 提出自己支援的版本、加密套件與金鑰交換參數。
2. Server 回覆參數與憑證鏈，並產生自己的金鑰交換資料。
3. 兩端各自計算出共同的會話金鑰，這是（橢圓曲線）Diffie-Hellman 的核心效果。
4. Client 驗證憑證鏈與主機名稱。
5. 之後的流量使用 AEAD 加密與認證。

對初學者最重要的是：身分驗證與加密是兩層不同的事情。沒有憑證驗證的加密，等於在黑暗中和一個自稱是你朋友的人握手。

## 憑證與主機名稱

瀏覽器檢查憑證是否由信任的根 CA 簽發、是否在有效期限內、是否適用於目前的網域名稱。任何一關不過，就會看到安全警告。這些檢查就是「鎖頭」真正代表的內容。

## 今日重點整理

- TLS 提供保密、完整與伺服器身分驗證。
- 握手先協商，再交換金鑰，最後進入 AEAD。
- 憑證驗證是信任的來源。
- 鎖頭不等於網站內容可信。

## 延伸思考

使用瀏覽器開發者工具，找一個 HTTPS 網站，看看它的憑證是由哪個 CA 簽發、有效期間多久，以及 SAN 中包含哪些網域名稱。
