## 學習目標

讀完這一課，你應該能分辨 Stored、Reflected 與 DOM-based XSS，並知道「依輸出情境編碼」為何比關鍵字過濾更可靠。

## 瀏覽器把資料當成程式碼

跨站腳本攻擊（XSS）發生在：應用程式把不可信的資料輸出到頁面，瀏覽器卻把它當成 HTML 或 JavaScript 執行。攻擊者可能竊取 Cookie、假造畫面或代替使用者操作。

常見三類：

- Stored：惡意內容先存進資料庫，之後每個訪客都看到。
- Reflected：內容來自請求參數，被原封不動回顯。
- DOM-based：問題發生在前端 JavaScript 操作頁面時，資料未安全處理。

## 輸出編碼才是根本解

不同的輸出位置需要不同的編碼：

- 放進 HTML 文字，要編碼 `<`、`>`、`&`、`"`、`'` 等。
- 放進屬性、JavaScript、URL，規則又不一樣。

單靠「把 script 字串刪掉」容易漏。正確做法是：渲染時依位置套用對應的編碼或 DOM 安全 API，例如用 `textContent` 而不是把字串當 HTML 塞進 `innerHTML`。

## 其他防線

內容安全政策（CSP）可以限制腳本來源，讓注入更難執行；Session Cookie 使用 HttpOnly 讓 JavaScript 無法直接讀取。這些是第二道防線，不能取代輸出編碼。

## 今日重點整理

- XSS 的根源是資料被當成程式碼執行。
- Stored、Reflected、DOM-based 只是路徑不同。
- 依輸出位置做正確編碼。
- CSP 與 HttpOnly 是減輕措施。
- 永遠不信任進入頁面的外部資料。

## 延伸思考

開啟任何一個有搜尋框的網站，輸入 `<b>test</b>` 再搜尋。如果結果頁把標籤渲染成粗體而不是文字，代表該頁面可能沒有對這類輸出做編碼。
