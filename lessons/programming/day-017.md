## 學習目標

讀完這一課，你應該能說明 CSRF 攻擊為什麼發生，以及 CSRF Token 與 SameSite Cookie 各自如何防禦。

## 瀏覽器會自動帶上 Cookie

登入網站後，瀏覽器記住 session Cookie。之後只要向同一網站發請求，瀏覽器通常會自動附上這個 Cookie，即使請求是從另一個惡意網頁偷偷發出的。

CSRF 攻擊就利用這一點：攻擊者誘使你造訪他的網頁，頁面背景偷偷送出「改密碼」、「轉帳」或「刪除資料」等請求。伺服器看到你的 Cookie，以為是你本人操作。

## CSRF Token

一種常見防禦是：伺服器產生一個隨機 token，放在你的表單或前端狀態裡。送出寫入請求時，要同時帶上這個 token，伺服器比對 cookie 與請求中的值。

攻擊者的惡意網頁拿不到你表單裡的 token（同源政策阻止它讀取其他網站的頁面內容），所以跨站偽造的請求會驗證失敗。這個專案的管理 API 就使用這種雙重驗證。

## SameSite Cookie

`SameSite=Lax` 或 `SameSite=Strict` 讓瀏覽器減少或不附帶跨站請求的 Cookie。這能擋住很多 CSRF，但通常仍被建議與 token 一起使用，作為分層防禦。

## 今日重點整理

- CSRF 是「利用你的登入狀態送出你沒想做的事」。
- GET 不應該執行狀態改變。
- CSRF Token 與 SameSite 是常見防禦。
- 登出前，瀏覽器裡的 session 就是你的身分。
- 防禦要放在伺服器端，不能只靠使用者小心。
